## 핵심 원칙

1. **역방향 설계**: 기획 단계에서 학습 목표와 미니 프로젝트를 먼저 정하고, 그 목표에 필요한 개념을 장에 배치한다.
2. **판단은 LLM, 확인은 코드**: 기획·설계·집필·검토는 LLM 이 하고, 실행·조립·추출·형식 검사는 코드가 한다.
3. **원본 하나**: 예제 코드와 그림 원본은 본문과 분리된 텍스트 파일로 두고, 책에는 조립할 때 끼워 넣는다. 실행한 코드와 책에 실린 코드는 항상 같다.
4. **실행으로 증명**: 실행 결과·그래프·실행 추적은 사람이나 LLM 이 적지 않고 실제로 실행해서 얻는다.
5. **겹겹의 검증 + 사람 승인**: 자동 검증은 "의심 목록"을 만들고, 최종 판단은 사람이 한다. 검토 → 수정 반복에는 한도를 둔다.
6. **그림 우선순위**: 코드에서 추출 > 실행해서 생성 > LLM 작성. 정답이 코드에 있으면 LLM 이 그리지 않는다.

## 현재 코드와의 관계

- 기존 대화 그래프(supervisor → 작업 노드 → human)는 **지시·승인 창구**로 유지한다.
- 장 하나를 만드는 긴 과정은 **하위 그래프**로 분리한다(`recursion_limit` 과 supervisor 호출 비용 때문).
- 오류 분류(`errors.py`), 재시도 정책, UTF-8 입출력, SQLite 체크포인트는 그대로 재사용한다.

## 먼저 처리할 문제

- **0단계: LLM 타임아웃 추가.** 현재 `app.py` 의 `ChatOpenAI` 에 타임아웃이 없어 한 호출이 openai 기본값(600초) × 재시도만큼 멈출 수 있다.
  실험에서 실제로 20분 넘게 응답 없이 멈춘 사례가 있었다([04_experiments.md](04_experiments.md) B-4). 본문 작성과 별개로 먼저 고친다.
