# 02. 내용 검증, 예제 코드, 미니 프로젝트

## 1. 내용 검증 6단계

| 층 | 무엇을 | 방법 | 자동화 |
|---|---|---|---|
| 1. 코드 실행 | 예제가 돌아가는가, 본문 출력과 실제 출력이 같은가 | 격리 실행 → 출력 비교, 프로젝트는 pytest, ruff lint | 완전 자동 |
| 2. 결정성 | 언제 실행해도 같은 결과인가 | `datetime.now()`, 시드 없는 `random`, 네트워크, `input()` 사용을 정적 검사. 날짜 고정·시드 사용 규칙 | 완전 자동 |
| 3. 사실·출처 | 주장마다 근거가 있는가 | 절에서 주장을 추출해 벡터 DB 출처 문단과 대조(LLM 판정), 근거 없는 주장 표시. 버전 관련 주장은 기획서의 대상 버전과 비교 | 반자동 |
| 4. 일관성 | 용어, 선행 개념, 교차 참조 | 장별 "도입한 개념" 목록으로 아직 배우지 않은 개념 사용 표시, 용어집과 표기 대조, "3장 참고" 같은 참조 대상 존재 확인 | 대부분 자동 |
| 5. 교육 품질 | 학습 목표를 다뤘는가, 난이도, 분량 | 장 설계서의 목표별 다룬 위치 대조, 평가 기준표로 LLM 채점, 분량 범위 검사 | 반자동 |
| 6. 사람 승인 | 최종 판단 | 기획서·장 설계서·장 원고 단계에서 검증 보고서를 보고 승인 또는 수정 지시 | 사람 |

- 검토 → 수정 반복은 `MAX_REVISIONS` 로 제한하고, 넘으면 사람에게 넘긴다.
- LLM 판정(3·5층)은 틀릴 수 있으므로 "통과" 판정이 아니라 **의심 목록**으로 쓰고, 판단은 6층이 한다.
- 그림에 대한 검증은 [03_visualization.md](03_visualization.md) 에 따로 정리한다.

- 본문 안에 코드 블록이 있으면 추출해 예제 파일로 옮기고 본문에는 include 표시만 남긴다.
- 모든 LLM 호출에 타임아웃과 재시도를 둔다(실험 B-4: 한 주제가 180초 타임아웃을 2회 연속 냄).

## 3. 예제 코드

- **본문과 분리된 실제 파일**로 둔다: `book/code/ch03/ex03_02_slicing.py`
  - 본문에는 `<!-- include: code/ch03/ex03_02_slicing.py -->` 만 두고 조립할 때 끼워 넣는다.
- **실행 결과도 파일**로 저장한다(`.out`). 본문의 "실행 결과"는 실제로 실행한 값이다.
- **예제 규칙** (장 설계서·문체 가이드에 명시)
  - 예제당 30줄 이내, 한 예제에 새 개념 하나
  - 앞 장에서 배운 것만 사용
  - 결과가 날마다 달라지지 않게 작성(날짜 고정, 난수 시드). 실험(B-3)에서 날짜 예제가 "오늘"이라서 우연히 일치한 사례가 있었다.
  - `input()` 을 쓰는 예제는 테스트용 입력 파일을 함께 둔다.
- **의존성**: 기획서에서 대상 Python·라이브러리 버전을 정하고, 장마다 고정한 뒤 깨끗한 가상환경에서 검증한다.
- **격리 실행** (`code_runner`)
  - 기본: 빈 임시 폴더, `python -I -X utf8`, 시간 제한, API 키 등이 없는 최소 환경변수
  - Docker 가 켜져 있으면 네트워크를 끊은 컨테이너에서 실행(프로젝트 코드처럼 길고 복잡한 코드에 권장)
  - 같은 코드를 다른 날짜·시각 조건에서도 같은 결과가 나오는지 확인한다(같은 날 2회 실행 비교만으로는 날짜 의존을 잡지 못함).

## 4. 미니 프로젝트

- **기획 단계에서 대단원(3~4개 장)마다 프로젝트 하나를 먼저 설계**한다: 기능 목록, 완성 모습, 필요한 개념.
- **장마다 한 단계씩 진행**한다. 예) 3장 할 일 추가 → 4장 파일 저장 → 5장 오류 처리.
  장 설계서에 "이 장에서 추가할 프로젝트 단계"를 적는다.
- **단계마다 완성본과 테스트**를 둔다: `projects/todo/step03/` + pytest
  - 테스트를 먼저 쓰고 코드가 통과해야 확정한다.
  - 독자는 단계마다 정답 코드와 비교할 수 있다.
  - 앞 장을 다시 쓰면 뒤 단계 테스트로 깨진 곳이 바로 드러난다.
- **연습문제**도 문제 + 정답 코드 + 테스트를 한 묶음으로 관리한다.
- 실행기를 언어별로 교체할 수 있게 만들어 두면 다른 언어 책으로 넓힐 수 있다(현재는 Python 만).

- 장을 다 쓰면 짧은 요약을 만들어 저장하고 다음 장을 쓸 때 사용한다.
